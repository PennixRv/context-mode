Manual setup for copilot-cli. Run:

copilot mcp add context-mode -- <NODE> <PKG>/server.mjs --agent copilot-cli

Hooks: add the hook block from `context-mode setup --print copilot-cli --json` to <HOME>/.copilot/hooks/context-mode.json
(keep your own entries).

Skill: put this in <HOME>/.copilot/skills/ctx-doctor/SKILL.md:

---
name: ctx-doctor
description: Diagnose context-mode as a table; use the native CLI for strictly read-only checks.
disable-model-invocation: true
---
Call the context-mode-ctx_doctor tool and show its table to the user unchanged only when its effects are within the authorized diagnostic scope. It can heal database files, write a report and index a large report. For strictly read-only work, use `context-mode doctor --agents <agent>` instead; select the actual host without changing its configuration.

List failed rows and their fixes. Do not automatically execute a Fix: installation, updates and removal belong to Pennix Lifecycle, while database repair needs its applicable authorization. Preserve unknown and failed results instead of retrying to hide them.

Skill: put this in <HOME>/.copilot/skills/ctx-stats/SKILL.md:

---
name: ctx-stats
description: Show how much context context-mode saved, as a detailed report.
disable-model-invocation: true
---
Call the context-mode-ctx_stats tool and show the text block of its reply to the user unchanged, inside a code block so the columns stay aligned. Add one sentence under it that names the largest saving.

Skill: put this in <HOME>/.copilot/skills/ctx-upgrade/SKILL.md:

---
name: ctx-upgrade
description: Show the Pennix Lifecycle route for updating context-mode.
disable-model-invocation: true
---
Call the context-mode-ctx_upgrade tool and show its owner guidance. Installation, updates and removal use Pennix Lifecycle through pennix-component-lifecycle. Diagnostics remain available separately and can perform upstream database self-healing.

Then restart the agent and check it: context-mode doctor --agents copilot-cli
