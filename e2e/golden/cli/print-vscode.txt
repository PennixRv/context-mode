Manual setup for vscode. Put this in <VSCODE_USER>/mcp.json
(If the folder or file is missing, create it. If the file exists, add the context-mode entry
and keep the rest. These paths are for this machine.)

{
  "servers": {
    "context-mode": {
      "command": "<NODE>",
      "args": [
        "<PKG>/server.mjs",
        "--agent",
        "vscode"
      ]
    }
  }
}

Hooks: add the hook block from `context-mode setup --print vscode --json` to <HOME>/.copilot/hooks/context-mode-vscode.json
(keep your own entries).

Skill: put this in <HOME>/.agents/skills/ctx-doctor/SKILL.md:

---
name: ctx-doctor
description: Diagnose context-mode as a table; use the native CLI for strictly read-only checks.
disable-model-invocation: true
---
Call the mcp__context_mode__ctx_doctor or context-mode-ctx_doctor or mcp_context-mode_ctx_doctor tool and show its table to the user unchanged only when its effects are within the authorized diagnostic scope. It can heal database files, write a report and index a large report. For strictly read-only work, use `context-mode doctor --agents <agent>` instead; select the actual host without changing its configuration.

List failed rows and their fixes. Do not automatically execute a Fix: installation, updates and removal belong to Pennix Lifecycle, while database repair needs its applicable authorization. Preserve unknown and failed results instead of retrying to hide them.
